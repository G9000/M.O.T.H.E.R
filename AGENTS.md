# M.O.T.H.E.R contributor guide

This is the owner's personal workspace, independent of AnimaOS. Preserve the README's approved title, centered poem and artwork. Keep its description brief and link to setup; put technical instructions in docs/.

Use the independent Cargo package and locked dependencies. The sole runtime uses the native redb Garden; there is no SQLite runtime, converter, fallback or Cargo feature. Run `cargo fmt --all -- --check`, `cargo test --locked`, `cargo build --release --locked`, and `cargo clippy --locked --all-targets --all-features -- -D warnings`. CI runs the same four commands on Linux, macOS and Windows. Audit the normal/build dependency tree to exclude `rusqlite` and `libsqlite3-sys`. Tests use synthetic context and owned temporary directories. The executable needs no Bun, Node or AnimaOS runtime.

Keep personal records, tokens, private exports and runtime databases out of Git. Private data belongs outside this repository. Do not import real conversations, modify live harness settings, install binaries or start external actions as a test. The legacy setup dashboard, app manager, launcher and model installer are removed. Native graph/v1 owner inbox review remains supported. Historical fixtures and reports are evidence, not current command instructions.

The v1 domain contract is src/contracts.rs; contracts/mcp-tools.json preserves its advertised tool schemas. Graph contracts live in src/garden/contracts.rs. GardenStore's redb transactions are the canonical authority for graph state and the native v1 compatibility view. Preserve atomic revision checks, immutable receipts, IDs, sources, corrections, retractions and uncertain outcomes. Client identity comes from private configuration, never tool arguments. Owner grant/restore/review and historical cutover operations are not MCP tools.

Runtime upgrades open existing native stores without changing generation. Old SQLite configurations fail explicitly; never create a replacement store or migrate implicitly. Preserve historical v1 data schemas and normalization/hash fixtures as archival compatibility artifacts. Restore validates a bundle before creating a fresh destination, commits all state atomically, changes generation, excludes grants and never executes actions.

Owners supply their own SOUL.md explicitly through `garden compat-init --soul` for the v1 view. Do not embed the maintainer's persona or discover one from an unrelated working directory. Existing workspaces use the stored persona snapshot. Editing a file alone never applies a persona change; the retired legacy soul CLI is not available. Harnesses retain their model, permissions and instruction hierarchy. Protocol tests are not proof that a real host has loaded the connection.

Living Memory proposals live in separate redb inbox tables, outside canonical recall and semantic indexing. MCP can propose/read but never approve them. `garden v1-inbox` and `garden inbox` open native owner review when stdin/stdout are terminals, and emit JSON listings when piped. An explicit reviewed JSON request can also use `garden review` (add `--graph` for graph review). Approval reuses the canonical transaction writer and atomically closes the proposal with its receipt. Preserve attribution, revision checks, restored-generation blocking and the validated optional inbox export extension. Existing native direct-write grants remain compatible; use `context:propose` for clients restricted to reviewed capture.

Use synthetic owner-private temporary roots; see docs/garden-service.md. The native owner service holds the sole database handle; stdio bridges use authenticated local IPC. Stop that service before direct owner database administration. Ordinary opens use GardenStore::open_active; raw opens are reserved for explicit owner journal recovery, backup validation and trusted synthetic tests. Preserve cutover fences and append-only journals. Historical journal status, exact grant reissue and eligible rollback remain supported; SQLite-source preparation and activation are removed. Runtime upgrades never activate a prepared destination or authorize deleting fences.
