# Connect AnimaOS from the terminal

Open M.O.T.H.E.R and press **n**, or run `mother connect animaos`.

1. Start AnimaOS on this computer. Keep the default `http://127.0.0.1:8080` address unless its local port differs.
2. Enter the **AnimaOS owner token**. This is AnimaOS's `ANIMA_LOCAL_ADMIN_TOKEN`, sent to its supported owner API. If AnimaOS also enables `ANIMAOS_RS_API_KEY`, enter that separate key in the optional field. These are AnimaOS credentials, not an OpenAI key. Both fields are masked and retained only for this setup session; paste them into the terminal, never into a chat.
3. Press Enter to load your agents. Choose one, then choose garden access: **Full garden** uses the companion grant; **Only selected records** uses an explicit allowlist, where an empty list shares no records. Both install a **Shared garden (additive)** provider: AnimaOS keeps its native memory, learning and configured personality. Full garden is initially selected. Press **p** to separately opt into the stored Mother personality when full garden access is selected. Shared grants cannot use that personality. Setup shows the latest 200 current records with titles, numbers and UUIDs; enter comma-separated numbers or record UUIDs for an allowlist and use PgDn/PgUp to scroll. The legacy tools-only option retains its older behavior.
4. Press Enter to review the exact agent, workspace, launch path, access and personality source, then Enter to connect. If this exact connection already has a primary-memory binding, setup shows that binding and stops for separate conversion review. Press **c** to authorize conversion, then Enter; conversion is off by default. Only the selected agent is configured.

M.O.T.H.E.R creates a separate private grant for each agent and role with exactly read and context:propose access. Companion and shared grants pin the selected agent as their subject. Shared grants expose only the explicit record-ID allowlist and never expose the persona; an empty list exposes no records. Companion can read canonical context and the owner persona. Both can submit Living Memory proposals for approval in `mother inbox`, rather than write canonical memory directly. The setup uses the running M.O.T.H.E.R executable; use a stable installed build for ongoing use.

The adapter saves an exact local stdio connection through AnimaOS's owner API, enables it with its current version and checks tool discovery. If AnimaOS requires individual tool review or blocks tools under its agent policy, complete that review in AnimaOS's Connectors > MCP screen. M.O.T.H.E.R does not override those permissions.

For companion/shared setup under Automatic tool policy, confirming setup authorizes snapshot review of six exact discovered tools: `mother_get_context`, `mother_search_context`, `mother_get_record`, `mother_propose_memory`, `mother_get_proposal` and `mother_get_receipt`. These support recall, selected proposals and outcome reconciliation. No direct canonical-write or owner-approval tool is reviewed. The adapter submits each current connection version, discovery ID and descriptor digest to the owner tool-review API, without creating extra execution grants, and reuses matching reviewed tools. Under Review policy, complete manual tool review and grants in AnimaOS, then return to Connect. Only after readiness and tool review does setup save the per-agent additive provider binding, pinned to the local workspace ID, restore generation, subject and connection. Older daemons without additive-provider metadata are rejected. AnimaOS continues local recall, capture and learning when Mother is unavailable. Ordinary turns are not uploaded; explicitly selected facts use AnimaOS's durable queue and become saved only after a canonical receipt. Read-only or review-required AnimaOS tool permissions can block sharing until the owner authorizes the relevant tools there.

Existing legacy grants and connections are preserved. New roles have separate client identities; setup never widens or rotates a grant. The existing connection-repair flow can explicitly replace this agent's older Mother connection to free a slot; it retains revision checks and leaves other tools alone. An existing primary-memory binding needs the separate conversion choice. Different bindings are preserved for inspection in AnimaOS settings. A changed allowlist on an existing role is rejected; review the existing grant and revoke/replace it explicitly through owner setup rather than expecting Connect to change its authority silently.

When ready, ask the AnimaOS agent:

> Load my M.O.T.H.E.R context. When I ask you to keep something, submit a proposal for my review inbox.

Discovery verifies that AnimaOS reached the MCP server and listed the required tools. A real conversation read/proposal is a separate acceptance step. Setup never claims that it ran a model or saved a personal memory merely because discovery passed.

The address must be a plain loopback HTTP address: `127.0.0.1`, `[::1]`, or `localhost`, which is rewritten to `127.0.0.1`. Redirects and remote addresses are rejected, so owner credentials stay on this computer. No tunnel is needed for this local connection. AnimaOS remains an optional external harness; M.O.T.H.E.R's database, persona, inbox and MCP work independently.

If a connection request times out, the TUI reports uncertainty. Returning to Connect first retrieves existing server state and reconciles an exact matching entry. It does not blindly create another server or replace different launch settings. Credentials are not saved; reopening setup requires entering them again.

Before a binding save, setup records the exact intended binding locally. If its response is lost, setup reads the owner API and compares the exact binding; it never blindly repeats the PUT. An unresolved outcome stays blocked for owner inspection. A successful setup is protocol evidence only; a real online/offline/recovery conversation remains a separate host acceptance step.

Tool reviews also save their exact intent before sending. After a lost response, returning to Connect reads current connection metadata and requires the same connection, expected next version, discovery ID, current descriptor and reviewed descriptor. A changed or missing result stays uncertain; setup never replays the review automatically.

Disable the additive provider in AnimaOS's Mother panel to stop automatic use while retaining queued shares and the connection. Stop or remove the connection in the MCP screen separately. Revoke its private Mother grant through owner setup when access should end. Disabling a provider does not revoke the key or authorize deleting shared records. The ChatGPT disconnect command controls only its own tunnel runtime.
