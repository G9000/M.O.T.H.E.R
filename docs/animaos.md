# Use Mother with AnimaOS

M.O.T.H.E.R remains an independent native redb workspace. AnimaOS is an optional external harness. The former Mother terminal adapter that authenticated to the AnimaOS owner API, provisioned grants, reviewed tools and installed a provider binding was removed with the legacy app. Updating Mother does not recreate or modify those settings.

Provision a distinct native credential for the selected agent with explicit [access policy](client-access.md). Follow [service setup](garden-service.md), then register the local stdio bridge in AnimaOS using the stable executable path and arguments `mcp`, `--config`, and the absolute service-config path. Use AnimaOS's supported owner settings and tool-review workflow. Its current version determines the available additive-provider and graph integration; Mother does not bypass that review or silently convert a primary-memory binding.

For reviewed context sharing, provision `read,context:propose`. Shared clients receive only selected v1 record IDs and no persona; companion persona visibility does not require personality adoption. Graph tools require separate explicit graph scopes and object policies. Discovery and tool admission grant no extra Mother authority.

Keep AnimaOS native memory, learning, agent isolation and configured personality under AnimaOS control. Test actual context reads, selected capture, owner approval, cross-client retrieval, offline behavior and revocation separately from discovery. The [historical additive-pairing report](additive-pairing-validation.md) records the retired Mother adapter's behavior; it is not current onboarding instructions. The [qualification evidence](benchmarks/garden-acceptance.md) records synthetic interoperability coverage and its source/platform limits.

No local stdio tunnel is required. Mother provides no current auto-pairing, owner-token prompt, connection replacement or provider-binding writer. Preserve an uncertain existing binding for inspection rather than repeating its setup effect. Existing live credentials, records and host settings are untouched by source updates.
