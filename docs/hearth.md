# Historical hearth boundary

Owner-triggered harness launching belonged to the retired legacy CLI. The current native executable has no `launch` command, launcher registry, run-log manager or automatic work dispatcher. Existing private launcher files and historical action records are not deleted or executed by an update.

Native v1 task assignments and action records remain attributed context under their existing MCP scopes. A handoff does not start another harness, stop a running job or grant execution permission. Each harness performs work under its own permissions. An uncertain action remains uncertain until reconciled; it must never trigger an automatic retry.

See [context and handoffs](context.md), [native setup](setup.md) and [historical validation](validation.md). Earlier hearth plans and launch measurements are archived evidence of the previous interface, not current commands.
